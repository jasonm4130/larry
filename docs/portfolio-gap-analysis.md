# Larry: Portfolio-Grade Gap Analysis

## 1. Executive summary

Larry is already in the top decile of ~2k-LOC hobby repos: clean `src/` layout, single `pyproject.toml` with ruff/pyright/pytest configured, a committed `uv.lock`, a correctly-split `[pi]` extra vs `dev` group, a mockable `JawDriver` Protocol, security-conscious `.gitignore` (verified: `.env` untracked), and genuinely senior-grade decision docs. The bones are right; what's missing is the connective tissue that turns "well-configured" into "demonstrably maintained." Three gaps do the most damage relative to their cost: **(1) there is no CI** — every gate is configured but nothing enforces it, and a green check is the single highest-signal artifact a reviewer scans for; **(2) the docs describe a different stack than the one shipping** (README/RESEARCH say Picovoice + Claude-via-OpenRouter; reality is OpenWakeWord + Grok-via-xAI), which makes a careful reader distrust everything else; and **(3) there is no demo media** of a physical, voice-driven talking skull — the one thing that makes this project special is invisible to a cold visitor. A sharp wrinkle: `pyright` currently exits 1 with 8 errors, so CI cannot simply be switched on — the typecheck must be made green first. Fix those three plus the trivial LICENSE/broken-install-command items and Larry reads as finished, credible, and rigorously engineered.

## 2. What good looks like

**Project structure & packaging.** The 2025-2026 default is `src/` layout + one `pyproject.toml` holding `[project]`, `[build-system]` (hatchling), and all tool config; uv with a committed `uv.lock`; runtime extras (PEP 621) kept distinct from local-only dev `[dependency-groups]` (PEP 735). `uv init --package` (astral-sh/uv) emits exactly this shape. Flask/Click are the gold standard for clean module layout at this scale; simonw/llm and simonw/datasette are the closest "single-author app with pluggable backends, no over-engineering" analogs. Restraint is a feature: a flat role-named module layout beats a hexagonal layer-cake until the codebase is far larger. **Larry already satisfies almost all of this** — the gaps are polish (LICENSE, doc drift, root clutter), not architecture.

**CI/CD & quality gates.** Use `astral-sh/setup-uv` (SHA-pinned, `enable-cache: true`) with `uv sync --locked` so a stale lock breaks the build. Run lint, format-check, typecheck, and tests as separate parallel gates; matrix only the test job across Python versions. Treat the typechecker as blocking, not advisory — astral-sh/uv and astral-sh/ruff's own repos are reference-grade here. SHA-pin third-party actions (the March 2025 tj-actions compromise hit 23,000+ repos), scope `permissions: contents: read`, add a `concurrency` cancel group, and pair Renovate/Dependabot with branch protection that *requires* the checks. smarlhens/python-boilerplate wires all of this into one pyproject. For a hobby app, OIDC Trusted Publishing and a coverage *gate* are optional; a passing badge is not.

**Documentation & presentation.** Lead with a 10-second hook: name, one-line tagline, then a demo GIF/MP4 *before* prose — httpie and alichtman/shallow-backup are textbook. For a hardware build the demo is non-negotiable: GitHub natively hosts a drag-dropped MP4, and a sub-5MB GIF autoplays. A small honest badge row (license, Python, CI, Ruff), a version-controlled Mermaid architecture diagram (not a drifting PNG), a copy-paste-and-it-works quickstart with the macOS/Pi split, and a BOM for the physical build. Pick one docstring style (Google) and enforce via ruff `D` rules. Ship the community meta-files (LICENSE, CONTRIBUTING, CODE_OF_CONDUCT, CHANGELOG). The winning tone pairs whimsy with hard numbers: GLaDOS publicly targets <600ms and explains the latency work was "the hard part"; openWakeWord publishes false-accept/reject methodology. Honesty about limitations (Larry's single-enclosure AEC, issue #1) reads as maturity, not weakness.

**Testing (async + hardware + external APIs).** Test the seams you own — branchy/stateful logic — not third-party SDKs or hardware drivers. Abstract hardware behind a Protocol and inject a *spy* mock that records commanded values (gpiozero's MockFactory pattern). Mock external APIs at the HTTP boundary with respx, never by patching your own functions; mark any live call `@pytest.mark.live` and exclude it by default. Standardize on `pytest-asyncio` strict mode + `AsyncMock` + a per-test timeout. Crucially, **Pipecat ships `pipecat.tests.utils.run_test`** — a harness that drives frames through a real pipeline and asserts the emitted frame sequence; it is the correct tool for the wake gate and turn-taking logic and it's already in-tree. Coverage is a diagnostic, not a target: ~70-80% over owned core logic (jaw mapper, wake gate, speaker_id, config), with drivers/`__main__`/CLI omitted. home-assistant/core is the reference for the marker-based unit/integration split.

**Operability & maintainability.** Config as one typed, validated, fail-fast `pydantic-settings` object loaded at startup, with `SecretStr` keys that mask in logs/tracebacks. One logging system configured once at the entrypoint (structlog with an `isatty()` dev/prod renderer switch), logging to stdout and letting systemd/journald own rotation. Graceful degradation around every cloud dep: bounded `tenacity` retries (its defaults retry *forever* — always set `stop_after_attempt` + `wait_exponential_jitter`), explicit timeouts, narrow `except` types, and a fallback path. Plain constructor injection from a single composition root — **no DI framework, no Vault, no circuit breaker, no `/healthz` Flask server** at 2k LOC; those are cargo-cult. Strict-from-the-start pyright is cheap now and painful to retrofit later.

## 3. Where Larry is

**Structure & packaging — strong.** `src/larry/` built by hatchling, console entrypoint `larry = larry.__main__:main`, clean `[pi]`/`dev` split, `uv.lock` committed, `.python-version` pins 3.12, thorough `.gitignore` (verified: `.env` untracked, no `__pycache__`, `data/` ignored). Remaining items are pure polish: **no LICENSE** (README says "TBD" — legally all-rights-reserved, which contradicts the open-toy framing), two `RESEARCH_*.md` files (~21KB) cluttering root, a dual-maintained version string, and unpinned (but locked) dep lower bounds.

**CI/CD & tooling — the weakest dimension.** Local config is good; automation is *zero*. No `.github/` at all. Worse, I verified the gate state: `ruff check` passes and `pytest` is green (4 tests), but **`pyright` exits 1 with 8 errors** (`pipeline.py:735-736` LLMSpecificMessage `.get`/index; `speaker_id.py:112` ndarray-vs-tuple; `jaw_pca9685.py:8` Pi-only `adafruit_servokit` import; plus `enroll.py:41`), and `ruff format --check` would reformat 3 files. So CI can't be naively switched on — it would be red on day one. No pre-commit, no coverage config, no badges, no Dependabot.

**Documentation — presents well but self-contradicts.** Strong README hook, clean stack table, copy-paste quickstarts, honest cost breakdown and "very early, built for fun" disclaimer; CLAUDE.md and the two RESEARCH docs are genuine portfolio assets (pick/reject/why/sources reasoning). But the README and `RESEARCH_larry_stack.md` describe **Picovoice Porcupine + Claude-via-OpenRouter** while the shipped code, CLAUDE.md and `.env.example` use **OpenWakeWord (local) + Grok-via-xAI preferred**. A top-to-bottom reader hits three contradictory accounts of the core architecture. Plus: a **literally broken install command** (`systemd/larry.service` — verified the real file is `larry@.service`, a templated unit), no LICENSE, no demo media, and the README omits `XAI_API_KEY` (the preferred path) and overstates TTS as "ElevenLabs v3" when the default is `eleven_turbo_v2_5`.

**Testing — mostly unrealized opportunity.** 4 passing tests over 2 files cover only the jaw mapper + mock (~60 of ~1,919 LOC). The behavioral core is untested: `WakeWordGate` (261 LOC, the highest-churn module — the last 5 commits are all bug fixes to it, none with a regression test), the two in-`pipeline.py` FrameProcessors, `SpeakerID`, `config` parsing, the AEC filter, and `ConversationLog`. No coverage tooling, no conftest, no Protocol-contract test. The good news: every heavy dep imports cleanly on macOS and the `run_test` harness ships in-tree — the gap is unused tooling, not a hard mocking problem.

**Code quality & operability — above average, two real weaknesses.** Secrets handling correct, logging production-minded, graceful degradation a recurring deliberate pattern (AEC pass-through fallback, feature-detected Speex NS, cue→live-TTS fallback). The real issues: (1) the pyright gate is red, and (2) `pipeline.py` is a 761-line god-module with a ~390-line `run()` mixing logging setup, prompt assembly, three inline processor classes, cue synthesis, and wiring. `config.py` does no validation (a bad numeric env var crashes with an opaque `ValueError`; `proactive_probability > 1` and negative angles pass silently). Minor: fire-and-forget cue tasks unreferenced (GC risk), cross-module private access (`speaker_id._current_speaker`), `memory.py` types `cfg: Any`.
